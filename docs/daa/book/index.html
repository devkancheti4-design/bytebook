Chapter 1 · Analysis of Algorithms

What Is an Algorithm?

The definition and five properties of an algorithm, how to write pseudocode, proving correctness with loop invariants, and the RAM model used to analyse running time.

An algorithm is a finite sequence of well-defined steps that takes some input and produces the correct output for every valid input. A program is an algorithm written in a particular language for a particular machine; the algorithm itself is the idea.

#The five properties (Knuth)

Property Meaning
Input zero or more quantities supplied from outside
Output at least one quantity produced
Definiteness every step is precise and unambiguous
Finiteness it always terminates after a finite number of steps
Effectiveness every step is basic enough to be carried out exactly, in finite time

"Keep stirring until it tastes good" fails definiteness. A loop that may never end fails finiteness.

#The design and analysis process

  1. Understand the problem — inputs, outputs, constraints, edge cases.
  2. Choose a design technique — brute force, divide and conquer, greedy, dynamic programming, backtracking …
  3. Write the algorithm — usually in pseudocode.
  4. Prove it correct for all inputs.
  5. Analyse its time and space as a function of the input size n.
  6. Implement and test.

#Proving correctness: loop invariants

A loop invariant is a statement that is true before every iteration of a loop. To prove an algorithm correct with one, show three things:

  1. Initialisation — it is true before the first iteration.
  2. Maintenance — if it is true before an iteration, it remains true before the next.
  3. Termination — when the loop ends, the invariant gives a useful property that shows the algorithm is correct.

For insertion sort, the invariant is: at the start of each iteration, the subarray A[1..j−1] holds the original first j−1 elements in sorted order. When the loop ends with j = n + 1, the whole array is sorted.

#The RAM model

To analyse algorithms independently of hardware, we use the Random Access Machine model:

  • Each simple operation (arithmetic, comparison, assignment, array access, function call) takes one unit of time.
  • Memory access is constant time.
  • Instructions run one after another (no parallelism).

The running time T(n) is the number of unit steps for an input of size n. For example, insertion sort does about n²/4 comparisons on average, so T(n) grows like n².

#Why analyse at all?

Suppose computer A runs 10⁹ instructions/second and computer B only 10⁷ — 100 times slower. Sort 10 million numbers:

Algorithm Steps Time
Computer A insertion sort, 2n² 2 × 10¹⁴ about 55 hours
Computer B merge sort, 50 n log₂ n about 1.2 × 10¹⁰ about 20 minutes

A better algorithm on a slow machine beats a worse algorithm on a fast machine by orders of magnitude. That is why this subject exists.

Frequently asked

"Define an algorithm and explain its characteristics" (the five properties) and "What is a loop invariant? Prove the correctness of insertion sort" are standard 5- and 10-mark questions.

Chapter 2 · Analysis of Algorithms

Asymptotic Notations

The formal definitions of O, Ω and Θ (plus little-o and little-ω), proving bounds by finding c and n₀, the order of growth, and the properties exams test.

Asymptotic analysis describes how running time grows as n becomes large, ignoring constant factors and small inputs. It lets us say "merge sort is faster than insertion sort" in a precise, machine-independent way.

#Big-O: upper bound

f(n) = O(g(n)) if there exist positive constants c and n₀ such that 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀.

f grows no faster than g. Example: 3n² + 10n + 5 = O(n²). Choose c = 4: we need 3n² + 10n + 5 ≤ 4n², i.e. n² − 10n − 5 ≥ 0, which holds for all n ≥ 11. So c = 4, n₀ = 11 works.

#Big-Omega: lower bound

f(n) = Ω(g(n)) if there exist positive constants c and n₀ such that 0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀.

f grows at least as fast as g. Example: 3n² + 10n + 5 = Ω(n²) with c = 3, n₀ = 1.

#Big-Theta: tight bound

f(n) = Θ(g(n)) if there exist positive constants c₁, c₂ and n₀ such that c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀.

f grows exactly as fast as g. f = Θ(g) if and only if f = O(g) and f = Ω(g). So 3n² + 10n + 5 = Θ(n²).

#Little-o and little-omega

Notation Meaning Analogy Example
f = O(g) f grows no faster than g ≤ n = O(n), n = O(n²)
f = Ω(g) f grows no slower than g ≥ n² = Ω(n)
f = Θ(g) same growth rate = 2n + 3 = Θ(n)
f = o(g) f grows strictly slower: f/g → 0 < n = o(n²), but n ≠ o(n)
f = ω(g) f grows strictly faster: f/g → ∞ > n² = ω(n)

#Order of growth

From slowest to fastest growing:

1 < log log n < log n < √n < n < n log n < n² < n³ < 2ⁿ < 3ⁿ < n! < nⁿ

A quick way to compare two functions: compute lim f(n)/g(n) as n → ∞. If it is 0, f = o(g); if it is a positive constant, f = Θ(g); if it is ∞, f = ω(g).

#Properties

  1. Transitivity: if f = O(g) and g = O(h), then f = O(h) (same for Ω, Θ).
  2. Reflexivity: f = O(f), f = Ω(f), f = Θ(f).
  3. Symmetry: f = Θ(g) if and only if g = Θ(f).
  4. Transpose symmetry: f = O(g) if and only if g = Ω(f).
  5. Sum rule: O(f) + O(g) = O(max(f, g)).
  6. Product rule: O(f) · O(g) = O(f · g).
  7. Constants vanish: O(c·f) = O(f) for any constant c > 0.
  8. Logs: log_a n = Θ(log_b n) for any bases a, b > 1, so the base is usually omitted.

#Checking bounds numerically

You can watch a ratio settle to a constant (Θ) or shrink to zero (little-o):

The first column approaches 3 (so f = Θ(n²)); the second tends to 0 (n log n = o(n²)); the third collapses to 0 incredibly fast (n² = o(2ⁿ)).

O is not "the worst case"

Big-O is an upper bound on a function; worst case is a property of inputs. You can give an O, Ω and Θ bound for the best case, the average case or the worst case. For example, insertion sort's best case is Θ(n) and its worst case is Θ(n²).

#Best, worst and average case

For linear search on n items:

  • Best case: key at position 1 → 1 comparison → Θ(1).
  • Worst case: key absent → n comparisons → Θ(n).
  • Average case: if the key is equally likely to be at any position, expected comparisons = (1 + 2 + … + n)/n = (n + 1)/2 → Θ(n).

#Amortised analysis

Some operations are usually cheap but occasionally expensive. Amortised analysis averages the cost over a sequence of operations (no probability involved).

Example: vector::push_back doubles the capacity when full, copying all elements. A single push can cost O(n), but over n pushes the total copying is 1 + 2 + 4 + … + n < 2n, so each push costs O(1) amortised.

The three classic methods are the aggregate, accounting and potential methods.

Chapter 4 · Analysis of Algorithms

Solving Recurrences & the Master Theorem

Solve recurrences with the substitution method, recursion trees and the Master Theorem — with its three cases, worked examples, and the cases it cannot handle.

#1. The substitution method

Guess the form of the solution, then prove it by induction.

Example: T(n) = 2T(⌊n/2⌋) + n. Guess T(n) ≤ c·n log n.

Assume it holds for n/2: T(n/2) ≤ c(n/2)log(n/2). Then

T(n) ≤ 2·c(n/2)log(n/2) + n = c·n log n − c·n·log 2 + n = c·n log n − c·n + n ≤ c·n log n whenever c ≥ 1.

So T(n) = O(n log n).

#2. The recursion-tree method

Draw the tree of recursive calls, add the cost at each level, then sum the levels.

T(n) = 2T(n/2) + n:

Level Nodes Cost per node Level total
0 1 n n
1 2 n/2 n
2 4 n/4 n
… … … …
log₂ n n 1 n

Total = n × (log₂ n + 1) = Θ(n log n).

#3. The Master Theorem

For recurrences of the form

T(n) = a·T(n/b) + f(n), with a ≥ 1, b > 1

compare f(n) with n^(log_b a) (the total cost of the leaves):

Case Condition Result
1 f(n) = O(n^(log_b a − ε)) for some ε > 0 — leaves dominate T(n) = Θ(n^(log_b a))
2 f(n) = Θ(n^(log_b a)) — every level costs the same T(n) = Θ(n^(log_b a) · log n)
3 f(n) = Ω(n^(log_b a + ε)) and a·f(n/b) ≤ c·f(n) for some c < 1 — root dominates T(n) = Θ(f(n))

#Worked examples

Recurrence a, b, n^(log_b a) f(n) Case Answer
T(n) = 2T(n/2) + n (merge sort) 2, 2, n n 2 Θ(n log n)
T(n) = T(n/2) + 1 (binary search) 1, 2, 1 1 2 Θ(log n)
T(n) = 8T(n/2) + n² 8, 2, n³ n² 1 Θ(n³)
T(n) = 7T(n/2) + n² (Strassen) 7, 2, n^2.81 n² 1 Θ(n^2.81)
T(n) = 2T(n/2) + n² 2, 2, n n² 3 Θ(n²)
T(n) = 3T(n/4) + n log n 3, 4, n^0.79 n log n 3 Θ(n log n)
T(n) = 4T(n/2) + n² 4, 2, n² n² 2 Θ(n² log n)

#Extended case 2

If f(n) = Θ(n^(log_b a) · logᵏ n) with k ≥ 0, then T(n) = Θ(n^(log_b a) · logᵏ⁺¹ n). For example, T(n) = 2T(n/2) + n log n = Θ(n log² n).

#When the Master Theorem does not apply

  • Subproblems of different sizes: T(n) = T(n/3) + T(2n/3) + n (use a recursion tree: Θ(n log n)).
  • Subtract-and-conquer forms: T(n) = T(n − 1) + n (unroll: Θ(n²)); T(n) = 2T(n − 1) + 1 (Θ(2ⁿ)).
  • f(n) falls in a gap between cases, e.g. T(n) = 2T(n/2) + n/log n.
  • a < 1 or b ≤ 1.

#Unrolling (iteration method)

For T(n) = T(n − 1) + n with T(1) = 1:

T(n) = n + T(n−1) = n + (n−1) + T(n−2) = … = n + (n−1) + … + 2 + 1 = n(n+1)/2 = Θ(n²).

#Check a solution by computing it

The ratio T(n)/(n log n) settles towards 1, confirming Θ(n log n).

Show your working

State a, b and f(n); compute n^(log_b a); say which case applies and why (compare the polynomial exponents); then write the answer. For case 3, also check the regularity condition a·f(n/b) ≤ c·f(n).

Chapter 5 · Divide and Conquer

Divide and Conquer

The divide, conquer, combine paradigm with full analysis of binary search, merge sort and quick sort, including quick sort's worst case and randomised pivots.

Divide and conquer solves a problem in three steps:

  1. Divide the problem into smaller subproblems of the same kind.
  2. Conquer the subproblems recursively (solve tiny ones directly).
  3. Combine the sub-solutions into a solution for the original problem.

Its running time naturally forms a recurrence T(n) = a·T(n/b) + D(n) + C(n), where D and C are the costs of dividing and combining — tailor-made for the Master Theorem.

#Binary search

  • Divide: compare with the middle element — O(1).
  • Conquer: search one half.
  • Combine: nothing.

T(n) = T(n/2) + O(1) → Θ(log n).

#Merge sort

  • Divide: split at the middle — O(1).
  • Conquer: sort both halves recursively.
  • Combine: merge two sorted halves — Θ(n).

T(n) = 2T(n/2) + Θ(n) → Θ(n log n) in every case.

#Quick sort

  • Divide: partition around a pivot — Θ(n). After partitioning, the pivot is in its final position.
  • Conquer: sort the two parts recursively.
  • Combine: nothing.
Case Partition split Recurrence Time
Best always in half T(n) = 2T(n/2) + n Θ(n log n)
Worst always 0 and n − 1 (sorted input, first/last pivot) T(n) = T(n − 1) + n Θ(n²)
Average random splits — Θ(n log n), about 1.39 n log₂ n comparisons

Even a consistently lopsided 9-to-1 split gives T(n) = T(9n/10) + T(n/10) + n = Θ(n log n). Only extreme imbalance hurts.

#Randomised quick sort

Picking the pivot uniformly at random makes the expected running time Θ(n log n) for every input — no specific input can trigger the worst case reliably.

#Merge sort vs quick sort

Merge sort Quick sort
Worst case Θ(n log n) Θ(n²) (rare with random pivots)
Extra space Θ(n) Θ(log n) stack
Stable yes no
Work happens in the combine step the divide step
In practice linked lists, external sorting arrays in memory (fast, cache-friendly)
Write the recurrence first

For any divide-and-conquer question, write the three steps with their costs, form the recurrence, then solve it with the Master Theorem. That structure earns most of the marks.

Chapter 6 · Divide and Conquer

More Divide and Conquer

Max–min with fewer comparisons, counting inversions with merge sort, Karatsuba's fast multiplication and Strassen's matrix multiplication.

#Finding the maximum and minimum

Finding both the max and min of n numbers naively takes 2(n − 1) comparisons. Divide and conquer does it in about 3n/2 − 2:

  • Split the array in half; find (max, min) of each half recursively.
  • Combine with two comparisons: max of the maxes, min of the mins.

T(n) = 2T(n/2) + 2, T(2) = 1, T(1) = 0 → T(n) = 3n/2 − 2 for n a power of two.

#Counting inversions

An inversion is a pair i < j with a[i] > a[j]. The count measures how "unsorted" an array is (used in ranking similarity, e.g. comparing two people's movie rankings). Checking all pairs is Θ(n²). Piggyback on merge sort: while merging, whenever an element from the right half is placed before remaining left-half elements, it forms an inversion with each of them.

Θ(n log n) instead of Θ(n²).

#Karatsuba multiplication

Multiplying two n-digit numbers the school way takes Θ(n²) digit operations. Split each number into halves: x = a·10^m + b and y = c·10^m + d. Then

x·y = ac·10^(2m) + (ad + bc)·10^m + bd.

That needs four half-size products: T(n) = 4T(n/2) + O(n) = Θ(n²) — no gain. Karatsuba's trick (1960) computes the middle term with one extra product:

ad + bc = (a + b)(c + d) − ac − bd

So only three multiplications are needed: T(n) = 3T(n/2) + O(n) = Θ(n^1.585).

#Strassen's matrix multiplication

Ordinary multiplication of two n × n matrices takes Θ(n³). Splitting each matrix into four (n/2) × (n/2) blocks gives 8 block multiplications: T(n) = 8T(n/2) + Θ(n²) = Θ(n³).

Strassen (1969) found a way to combine the blocks using only 7 multiplications (and 18 additions/subtractions):

Product Formula
M₁ (A₁₁ + A₂₂)(B₁₁ + B₂₂)
M₂ (A₂₁ + A₂₂)B₁₁
M₃ A₁₁(B₁₂ − B₂₂)
M₄ A₂₂(B₂₁ − B₁₁)
M₅ (A₁₁ + A₁₂)B₂₂
M₆ (A₂₁ − A₁₁)(B₁₁ + B₁₂)
M₇ (A₁₂ − A₂₂)(B₂₁ + B₂₂)

C₁₁ = M₁ + M₄ − M₅ + M₇, C₁₂ = M₃ + M₅, C₂₁ = M₂ + M₄, C₂₂ = M₁ − M₂ + M₃ + M₆.

T(n) = 7T(n/2) + Θ(n²) = Θ(n^log₂7) ≈ Θ(n^2.81).

Other divide-and-conquer classics

Closest pair of points in Θ(n log n), fast Fourier transform (FFT) for polynomial multiplication in Θ(n log n), and the median-of-medians selection algorithm that finds the k-th smallest element in worst-case Θ(n).

Chapter 7 · Greedy Algorithms

The Greedy Method

Make the locally best choice at every step: the greedy-choice property, activity selection, fractional knapsack, job sequencing with deadlines, and when greedy fails.

A greedy algorithm builds a solution step by step, always making the choice that looks best right now, and never reconsidering it. Greedy algorithms are simple and fast — but they are only correct for problems with two properties:

  1. Greedy-choice property — a globally optimal solution can be reached by making a locally optimal choice.
  2. Optimal substructure — an optimal solution contains optimal solutions to its subproblems.

#When greedy fails

Give change for 6 using coins {1, 3, 4}. Greedy takes the largest coin first: 4 + 1 + 1 = 3 coins. But 3 + 3 = 2 coins. Greedy is wrong here — that problem needs dynamic programming. With Indian currency denominations (1, 2, 5, 10, 20, 50 …), greedy happens to be optimal.

#Activity selection

Given activities with start and finish times, choose the maximum number of non-overlapping activities (one room, many meetings).

Greedy rule: sort by finish time and repeatedly pick the activity that finishes earliest among those compatible with what you already picked. Finishing early leaves the most room for the rest.

Time: Θ(n log n) for sorting, then Θ(n).

#Fractional knapsack

A thief's knapsack holds weight W. Items have values and weights, and fractions of items may be taken (gold dust, not gold bars). Maximise value.

Greedy rule: take items in decreasing order of value per unit weight, taking a fraction of the last one if it does not fit.

Fractional vs 0/1 knapsack

Greedy by ratio is optimal only for the fractional version. In the 0/1 knapsack (take an item whole or not at all), it fails: with the items above, greedy takes silver + gold for 160, but gold + silk gives 220. The 0/1 version needs dynamic programming.

#Job sequencing with deadlines

Each job takes one unit of time, has a deadline and a profit earned only if finished by its deadline. Maximise total profit.

Greedy rule: consider jobs in decreasing order of profit, and schedule each in the latest free slot on or before its deadline.

Chapter 8 · Greedy Algorithms

Huffman Coding

Optimal prefix-free codes for data compression: why prefix codes, building the Huffman tree with a min-priority queue, reading off codes, and computing the compressed size.

Text is stored with fixed-length codes: ASCII uses 8 bits for every character. But in English text, e is far more common than z. Huffman coding (David Huffman, 1952) gives frequent characters short codes and rare characters long codes, producing an optimal compression for a given set of frequencies. It is used inside ZIP, gzip, PNG and JPEG.

#Prefix-free codes

To decode a bit stream without separators, no code may be a prefix of another. If a = 0 and b = 01, then 01 could be "ab…" or "b". Huffman codes are always prefix-free because every character sits at a leaf of a binary tree.

#The algorithm

  1. Create a leaf node for each character with its frequency, and put them all in a min-priority queue.
  2. Repeat until one node remains:
    • Remove the two lowest-frequency nodes.
    • Create a new internal node with these two as children and frequency = their sum.
    • Insert it back into the queue.
  3. The remaining node is the root. Label left edges 0 and right edges 1; each character's code is the path from the root.

The greedy choice is "merge the two rarest symbols first", which pushes them deepest into the tree.

#Example

Character a b c d e f
Frequency 45 13 12 16 9 5

Merges: f(5)+e(9)=14 → c(12)+b(13)=25 → 14+d(16)=30 → 25+30=55 → a(45)+55=100.

The program's codes may differ from the diagram in which child goes left (ties can be broken either way), but the code lengths and total bits are always the same: 224 bits versus 300 for a fixed 3-bit code.

#Analysis

  • n − 1 merges, each doing O(log n) priority-queue operations → O(n log n).
  • Huffman's code is optimal among prefix codes: no other prefix code gives a smaller total Σ freq × code length.

#Decoding

Start at the root; read bits, going left on 0 and right on 1; when you reach a leaf, output its character and return to the root. With the codes in the diagram, 0101100 splits in only one way, 0 | 101 | 100, and decodes to abc.

Typical question

"Construct the Huffman tree and codes for the given frequencies, and find the average code length." Average length = Σ(freq × length) / Σ freq. For the example: 224 / 100 = 2.24 bits per character.

Chapter 9 · Greedy Algorithms

Minimum Spanning Trees

Connect every vertex at minimum total cost: spanning trees, Kruskal's algorithm with union-find, Prim's algorithm with a priority queue, traced on the same graph.

A spanning tree of a connected, undirected graph is a subset of its edges that connects all vertices with no cycles — exactly V − 1 edges. A minimum spanning tree (MST) is a spanning tree with the smallest possible total edge weight.

Uses: laying cable or pipelines to connect cities at minimum cost, designing networks, clustering, and approximating harder problems like TSP.

#Kruskal's algorithm

Greedy rule: consider edges from lightest to heaviest; add an edge if it does not create a cycle.

To test "would this edge create a cycle?" quickly, Kruskal uses a union-find (disjoint set) structure: each vertex starts in its own set; an edge (u, v) creates a cycle exactly when u and v are already in the same set.

Time: sorting dominates → O(E log E) (= O(E log V)).

#Prim's algorithm

Greedy rule: grow one tree from a start vertex; at each step add the cheapest edge connecting the tree to a new vertex. A min-priority queue holds the candidate edges.

Time with a binary heap: O(E log V). With an adjacency matrix and no heap: O(V²), which is better for dense graphs.

#Kruskal vs Prim

Kruskal Prim
Grows a forest that merges into one tree a single tree
Picks globally lightest safe edge lightest edge leaving the tree
Data structure sorted edges + union-find priority queue
Time O(E log E) O(E log V) with a heap; O(V²) with a matrix
Better for sparse graphs dense graphs

Both always find a minimum spanning tree. If all edge weights are distinct, the MST is unique, so both find the same one.

Trace in a table

For Kruskal, list edges in sorted order and mark each "take" or "reject (cycle)". For Prim, show the tree after each step and the edge added. Always state the final MST weight.

Chapter 10 · Greedy Algorithms

Shortest Paths: Dijkstra & Bellman–Ford

Single-source shortest paths in weighted graphs: relaxation, Dijkstra's greedy algorithm with a priority queue, why it fails on negative edges, and Bellman–Ford with negative-cycle detection.

Given a weighted graph and a source vertex s, find the shortest-path distance from s to every other vertex. (BFS solves this only when all edges have the same weight.)

#Relaxation

Both algorithms repeatedly relax edges. For an edge u → v with weight w:

"If going through u gives a shorter route to v, use it."

#Dijkstra's algorithm

Greedy rule: repeatedly pick the unvisited vertex with the smallest known distance, mark it final, and relax its outgoing edges. Works when all edge weights are non-negative.

Time with a binary heap: O((V + E) log V).

Negative edges break Dijkstra

Dijkstra assumes that once a vertex is finalised, no later path can be shorter. A negative edge discovered later can violate that. Use Bellman–Ford instead.

#Bellman–Ford

Relax every edge, V − 1 times. After round k, every shortest path using at most k edges is correct, and a shortest path never needs more than V − 1 edges. A V-th round that still improves some distance proves a negative cycle is reachable (no shortest path exists).

Time: O(V · E) — slower than Dijkstra but handles negative weights.

#Comparison

Dynamic Programming

Solve each subproblem once: overlapping subproblems and optimal substructure, memoisation vs tabulation, and DP solutions for Fibonacci and coin change.

Dynamic programming (DP) solves problems by combining solutions to subproblems — like divide and conquer — but for problems whose subproblems overlap. Instead of recomputing a subproblem every time it appears, DP solves it once and stores the answer.

A problem suits DP when it has:

  1. Optimal substructure — an optimal solution is built from optimal solutions to subproblems.
  2. Overlapping subproblems — the same subproblems recur many times.

#The problem with plain recursion

fib(30) makes over a million calls to compute only 31 distinct values. That is exponential waste.

Overhead function calls, recursion depth none

Space saving tricks harder easy (keep only needed rows)

#The DP recipe

  1. Define the state: what does dp[i] (or dp[i][j]) mean, in words?
  2. Write the recurrence: how does a state depend on smaller states?
  3. Base cases.
  4. Fill order: make sure dependencies are computed first.
  5. Answer: which cell holds the final result? (Optionally trace back the choices.)

#Example: coin change

Coins {1, 3, 4}, amount 6. Greedy gave 3 coins; DP finds the true minimum.

State: dp[x] = minimum number of coins that make amount x. Recurrence: dp[x] = 1 + min(dp[x − c]) over coins c ≤ x. Base: dp[0] = 0.

Time O(amount × coins). The second loop answers a different question — how many combinations — with the coin loop outside so each combination is counted once.

0/1 Knapsack

Choose whole items to maximise value within a weight limit: the DP table, the recurrence, tracing back the chosen items, and a space-optimised version.

You have n items, each with a weight and a value, and a knapsack of capacity W. Each item is taken whole or not at all (0 or 1). Maximise the total value without exceeding W.

Greedy by value-per-weight fails here (see the greedy lesson); trying all 2ⁿ subsets is too slow. DP solves it in O(nW).

#State and recurrence

State: dp[i][w] = the best value achievable using the first i items with capacity w.

For item i (weight wᵢ, value vᵢ), either skip it or take it (if it fits):

dp[i][w] = dp[i−1][w] if wᵢ > w dp[i][w] = max(dp[i−1][w], vᵢ + dp[i−1][w − wᵢ]) otherwise

Base: dp[0][w] = 0 (no items) and dp[i][0] = 0 (no capacity). Answer: dp[n][W].

Longest Common Subsequence

Find the longest sequence common to two strings: subsequences vs substrings, the LCS table and recurrence, traceback, and the related edit-distance problem.

A subsequence keeps characters in order but may skip some: "ACE" is a subsequence of "ABCDE". (A substring must be contiguous.) The longest common subsequence (LCS) of two strings is the longest sequence that is a subsequence of both.

LCS powers diff tools, version control, DNA sequence alignment and plagiarism detection.

#Recurrence

State: L[i][j] = length of the LCS of the first i characters of X and the first j characters of Y.

L[i][j] = 0 if i = 0 or j = 0 L[i][j] = L[i−1][j−1] + 1 if X[i] = Y[j] L[i][j] = max(L[i−1][j], L[i][j−1]) otherwise

If the last characters match, they extend the LCS of the shorter prefixes. If not, drop one of them — whichever gives the longer result.

#Watch it fill

Time and space O(mn). Brute force would check all 2ᵐ subsequences of X.

More than one LCS

"ABCBDAB" and "BDCABA" have several LCSs of length 4: BCBA, BDAB and BCAB. The traceback finds one; which one depends on how ties are broken.

#Related: edit distance

The edit distance (Levenshtein distance) is the minimum number of single-character insertions, deletions and substitutions that turn one string into another — the basis of spell checkers.

D[i][j] = D[i−1][j−1] if X[i] = Y[j] D[i][j] = 1 + min(D[i−1][j] (delete), D[i][j−1] (insert), D[i−1][j−1] (substitute)) otherwise

Matrix Chain Multiplication

Find the cheapest way to parenthesise a product of matrices: why order matters, the m[i][j] recurrence, filling the table by chain length, and printing the optimal parenthesisation.

Multiplying a p × q matrix by a q × r matrix takes p·q·r scalar multiplications. Matrix multiplication is associative — (AB)C = A(BC) — but the cost depends on the order.

Example: A is 10 × 100, B is 100 × 5, C is 5 × 50.

Order Cost
(AB)C 10·100·5 + 10·5·50 = 5,000 + 2,500 = 7,500
A(BC) 100·5·50 + 10·100·50 = 25,000 + 50,000 = 75,000

Ten times difference for three matrices. For a chain of n matrices, the number of parenthesisations grows exponentially (the Catalan numbers), so we use DP.

#Recurrence

Matrix Aᵢ has dimensions p[i−1] × p[i]. State: m[i][j] = minimum cost to multiply Aᵢ … Aⱼ.

m[i][i] = 0 m[i][j] = min over i ≤ k < j of ( m[i][k] + m[k+1][j] + p[i−1]·p[k]·p[j] )

Split the chain after Aₖ: multiply the left part, the right part, then the two results. Store the best k in s[i][j] to rebuild the parenthesisation.

Fill order: by increasing chain length L = 2, 3, …, n (each cell needs shorter chains).

This is the classic CLRS example: the answer is 15,125 with ((A1(A2A3))((A4A5)A6)).

Time O(n³) (n² cells, each trying up to n splits), space O(n²).

How to present it

Draw the m table (upper triangle) and the s table. Fill them diagonal by diagonal, showing the k computation for at least one cell, e.g. m[2][5] = min over k = 2, 3, 4, then print the parenthesisation from s.

Chapter 15 · Dynamic Programming

All-Pairs Shortest Paths: Floyd–Warshall

Shortest distances between every pair of vertices with a three-loop DP, its recurrence over intermediate vertices, negative-cycle detection, and Warshall's transitive closure.

Dijkstra and Bellman–Ford find shortest paths from one source. Floyd–Warshall finds them between all pairs in one go, works with negative edges (but not negative cycles), and is just three nested loops.

#The idea

Number the vertices 1 … n. Let dᵏ[i][j] be the shortest distance from i to j using only vertices 1 … k as intermediate stops. Either the best path avoids vertex k, or it goes through k:

dᵏ[i][j] = min( dᵏ⁻¹[i][j], dᵏ⁻¹[i][k] + dᵏ⁻¹[k][j] )

Start with d⁰ = the edge weights (∞ where there is no edge, 0 on the diagonal). After k = n, every vertex has been allowed as an intermediate: the matrix holds all shortest distances. The table can be updated in place.

Time Θ(V³), space Θ(V²). It is the best choice for dense graphs or when you need every pair. A negative value on the diagonal at the end means a negative cycle.

#Warshall's algorithm: transitive closure

Replace min and + with OR and AND to answer "is there any path from i to j?". The result is the transitive closure of the graph — see Relations in Discrete Mathematics.

Chapter 16 · Search, Graphs & Complexity

Backtracking

Explore a state-space tree and abandon dead ends early: the N-Queens problem, subset sum, graph colouring and Hamiltonian cycles.

Backtracking builds a solution one choice at a time. After each choice it checks whether the partial solution can still lead to a valid answer; if not, it undoes the last choice (backtracks) and tries the next option. It is a depth-first search of the state-space tree with pruning.

#N-Queens

Place N queens on an N × N chessboard so that no two attack each other (same row, column or diagonal). Place one queen per row; for each row, try every column that is safe.

Without pruning there would be 8⁸ ≈ 16.7 million placements for N = 8; backtracking explores about two thousand nodes.

#Subset sum

Given positive integers and a target, find subsets that add up exactly to the target. For each number, branch on include or exclude; prune when the sum exceeds the target or the remaining numbers cannot reach it.

#Graph colouring

Colour the vertices with at most m colours so that no two adjacent vertices share a colour. Try colours for each vertex in turn, backtracking on conflicts.

The smallest m that works is the graph's chromatic number. Deciding whether a graph is 3-colourable is NP-complete.

#Hamiltonian cycle

A Hamiltonian cycle visits every vertex exactly once and returns to the start. Backtracking extends a path one unvisited neighbour at a time and backtracks at dead ends. No polynomial algorithm is known; it is NP-complete.

Problem Choice at each level Pruning test
N-Queens column for the next row no attack
Subset sum include / exclude next number sum too big, or cannot reach target
Graph colouring colour for the next vertex no neighbour has that colour

Branch and Bound

Optimisation by bounding: FIFO, LIFO and least-cost branch and bound, solving 0/1 knapsack with an upper bound, and the travelling salesperson problem.

Branch and bound (B&B) is used for optimisation problems (find the best solution, not all solutions). Like backtracking, it explores a state-space tree, but at every node it computes a bound — the best value any solution in that subtree could possibly achieve. If the bound is no better than the best complete solution found so far, the whole subtree is pruned.

Backtracking Branch and bound
Problem type decision / find all solutions optimisation
Search order depth-first FIFO (BFS), LIFO (DFS) or least-cost (best-first)
Pruning when a constraint fails when the bound cannot beat the best so far
Examples N-Queens, Sudoku 0/1 knapsack, TSP, job assignment

#Search strategies

  • FIFO B&B — live nodes in a queue (breadth-first).
  • LIFO B&B — live nodes in a stack (depth-first).
  • Least-cost (LC) B&B — live nodes in a priority queue, always expanding the most promising node first. Usually the fastest to reach the optimum.

#0/1 knapsack with B&B

At each node, decide whether to include the next item. The upper bound of a node is its current value plus the value obtainable by filling the remaining capacity fractionally with the remaining items (sorted by value/weight). Since the fractional relaxation is never worse than the real 0/1 answer, it is a valid optimistic bound.

#Travelling salesperson problem (TSP)

Visit every city exactly once and return home with the minimum total distance. Brute force checks (n − 1)! tours. B&B builds tours city by city and bounds each partial tour with a lower bound — for example, the cost so far plus, for every unvisited city, half the sum of its two cheapest edges, or the reduced-cost-matrix bound used in many textbooks. Partial tours whose bound already exceeds the best tour found are pruned.

TSP is NP-hard: B&B makes it practical for moderate sizes, but no polynomial algorithm is known. A DP solution (Held–Karp) runs in O(n² · 2ⁿ), far better than O(n!).

Chapter 18 · Search, Graphs & Complexity

Topological Sort & Connectivity

Order tasks with dependencies using Kahn's algorithm and DFS, find connected and strongly connected components, and detect cycles in directed graphs.

#Topological sort

A topological order of a directed acyclic graph (DAG) lists the vertices so that every edge u → v has u before v. It answers "in what order can I do these tasks?" — course prerequisites, build systems, spreadsheet recalculation, package installation.

#Kahn's algorithm (BFS)

Repeatedly output a vertex with in-degree 0 (no remaining prerequisites) and remove its outgoing edges.

If some vertices never reach in-degree 0, the graph has a cycle and no topological order exists. Time O(V + E).

#DFS-based topological sort

Run DFS; when a vertex finishes (all its descendants are done), push it onto a stack. Reading the stack top-down gives a topological order.

The three DFS states also detect cycles in directed graphs: reaching a vertex that is still on the current path (state 1) means a back edge, hence a cycle.

#Connected components

In an undirected graph, run BFS or DFS from each unvisited vertex; each run discovers one connected component. O(V + E).

#Strongly connected components

In a directed graph, a strongly connected component (SCC) is a maximal set of vertices where every vertex can reach every other. Kosaraju's algorithm finds all SCCs in O(V + E):

  1. Run DFS on the graph and record vertices by finish time.
  2. Reverse every edge.
  3. Run DFS on the reversed graph in decreasing finish order; each tree found is one SCC.

String Matching

Find a pattern in a text: the naive algorithm, Rabin–Karp's rolling hash, and the Knuth–Morris–Pratt algorithm with its prefix function — with complexities.

Given a text T of length n and a pattern P of length m, find every position where P occurs in T. This runs every time you press Ctrl+F, search DNA databases, or filter spam.

#Naive algorithm

Try every alignment of P against T and compare character by character.

Worst case O((n − m + 1) · m), e.g. T = "aaaa…a", P = "aaab".

#Rabin–Karp

Compare hash values first, and only compare characters when the hashes match. The trick is a rolling hash: the hash of the next window is computed from the previous one in O(1) by removing the leading character and adding the trailing one.

Expected time O(n + m); worst case O(nm) if many hashes collide (a "spurious hit"). Rabin–Karp shines when searching for many patterns at once.

#Knuth–Morris–Pratt (KMP)

When a mismatch happens, the naive algorithm slides the pattern by one and re-checks characters it has already seen. KMP never moves backwards in the text. It precomputes the prefix function π (also called the LPS array): π[q] = the length of the longest proper prefix of P[0..q] that is also a suffix of it. On a mismatch, it shifts the pattern so that this already-matched prefix lines up.

For P = "ABABCABAB": π = [0, 0, 1, 2, 0, 1, 2, 3, 4].

Preprocessing O(m) + matching O(n) = O(n + m) in the worst case.

Rabin–Karp O(m) O((n − m + 1)m), expected O(n + m) rolling hash

P, NP, NP-Complete & NP-Hard

Tractable and intractable problems: decision problems, the classes P and NP, polynomial-time reductions, NP-complete and NP-hard problems, Cook's theorem, and coping with hardness.

Some problems are solved in polynomial time — sorting, shortest paths, MST. Others, like TSP, 0/1 knapsack and graph colouring, have resisted every attempt for decades. Complexity theory explains this difference.

#Decision problems

Complexity classes are defined for decision problems, whose answer is yes or no. Optimisation problems have decision versions: "Is there a tour of length ≤ k?" instead of "What is the shortest tour?". If you can solve one quickly, you can usually solve the other.

#The class P

P = decision problems that can be solved in polynomial time, O(nᵏ) for some constant k. These are considered tractable.

Examples: sorting, searching, shortest paths, MST, matching, primality testing (AKS, 2002).

#The class NP

NP (nondeterministic polynomial) = decision problems whose yes-answers can be verified in polynomial time, given a suitable certificate (a proposed solution).

Example — SUBSET-SUM: "Do some of these numbers add up to 15?" Finding a subset may be hard, but checking a proposed subset is easy: add it up.

Every problem in P is also in NP (if you can solve it, you can verify it), so P ⊆ NP.

#Reductions

Problem A reduces to problem B (A ≤ₚ B) if any instance of A can be transformed in polynomial time into an instance of B with the same answer. Then B is at least as hard as A: a fast algorithm for B would give a fast algorithm for A.

#NP-complete and NP-hard

  • NP-hard: every problem in NP reduces to it. It is at least as hard as anything in NP (it need not be in NP itself, and need not be a decision problem).
  • NP-complete (NPC): NP-hard and in NP — the hardest problems inside NP.

Cook–Levin theorem (1971): SAT (Boolean satisfiability) is NP-complete. It was the first. To show a new problem X is NP-complete:

  1. Show X ∈ NP (a certificate can be checked in polynomial time).
  2. Reduce a known NP-complete problem to X.

#Famous NP-complete problems

Problem Question
SAT / 3-SAT Can the Boolean formula be made true?
Clique Does the graph contain k mutually adjacent vertices?
Vertex cover Can k vertices touch every edge?
Independent set Are there k pairwise non-adjacent vertices?

#P vs NP

Nobody knows whether P = NP. If any single NP-complete problem had a polynomial algorithm, every NP problem would — so P would equal NP. Most researchers believe P ≠ NP. It is one of the seven Millennium Prize Problems (US $1 million prize).

#Coping with NP-hard problems

  1. Exact but exponential: backtracking, branch and bound, DP (fine for small n).
  2. Approximation algorithms with guaranteed ratios: e.g. a 2-approximation for vertex cover; for metric TSP, the MST-based tour is at most 2 × optimal.
  3. Heuristics: greedy, local search, simulated annealing, genetic algorithms — good answers quickly, no guarantee.
  4. Special cases: 2-SAT and 2-colouring are in P; knapsack with small W uses the O(nW) DP.
Definitions to learn word for word

P: solvable in polynomial time. NP: verifiable in polynomial time. NP-hard: every NP problem reduces to it in polynomial time. NP-complete: in NP and NP-hard. Then give one example of each.
