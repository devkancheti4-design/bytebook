Chapter 1 · From C to C++

C++ Introduction

Where C++ came from, what it adds to C, your first program with iostream and namespaces, and how to compile it.

C++ was created by Bjarne Stroustrup at Bell Labs, starting in 1979 as "C with Classes". It keeps almost everything from C — the speed, the pointers, the control over memory — and adds tools for organising large programs: classes and objects, references, function overloading, templates, exceptions and a huge Standard Template Library (STL).

C++ powers game engines (Unreal), browsers (Chrome, Firefox), databases, trading systems, compilers and most performance-critical software you use.

#Namespaces and using

A namespace groups names to avoid clashes — two libraries can both have a sort function if they live in different namespaces. Writing std:: everywhere is precise; using namespace std; lets you drop the prefix:

It is fine in small programs and exam answers. In large projects and header files, prefer writing std:: so names from different libraries never collide.

What C++ adds to functions: pass by reference, const references, function overloading, default arguments and inline functions.

#Pass by reference

A reference parameter lets a function change the caller's variable — without pointers:

Compare the three ways of passing an argument:

Call f(x) f(&x) f(x)

#const references

Passing a large object (like a long string or vector) by value copies the whole thing. Pass it as a const reference instead: no copy, and the function promises not to change it.

Rule of thumb

Small built-in types (int, double, char): pass by value. Objects (string, vector, your own classes): pass by const &, or by & if the function must modify them.

#Function overloading

Several functions can share a name if their parameter lists differ (in number or types). The compiler picks the right one from the arguments — this is compile-time polymorphism.

Return type alone is not enough

int f(int) and double f(int) cannot coexist: a call like f(3) would be ambiguous. Overloads must differ in their parameters.

Chapter 4 · Classes & Objects

OOP Concepts

Why object-oriented programming exists, the difference from procedural code, and the four pillars — encapsulation, abstraction, inheritance and polymorphism.

Procedural programming (what you did in C) organises a program around functions that act on separate data. As programs grow, any function can modify any data, and changes ripple everywhere.

Object-oriented programming (OOP) organises a program around objects — bundles of data (attributes) and the functions that operate on it (methods). A bank account object owns its balance; nothing else may change it except through the account's own deposit and withdraw methods.

Procedural Object-oriented
program = functions + separate data program = interacting objects
top-down design bottom-up design: build objects, then combine them
data is often global and exposed data is hidden inside objects
harder to reuse and extend reuse through inheritance and composition
C, Pascal, Fortran C++, Java, Python, C#

#Class and object

  • A class is a blueprint: it describes what data and behaviour objects of that kind have.
  • An object is an instance of a class: a real thing built from the blueprint, with its own data.

Car is a class; your red Swift with registration KA-01-1234 is an object.

#The four pillars

#1. Encapsulation

Bundling data with the methods that use it, and hiding the data from outside code (making it private). Outside code must go through public methods, which can check every change.

A capsule hides the medicine inside; you just swallow it.

#2. Abstraction

Showing what an object does while hiding how it does it. You call car.start() without knowing about fuel injection. In C++, abstraction comes from public interfaces, abstract classes and header files.

#3. Inheritance

Creating a new class from an existing one, reusing its members and adding or changing some. A Student and a Teacher can both inherit from Person. It models an is-a relationship: a Student is a Person.

#4. Polymorphism

"Many forms": the same call behaves differently depending on the object. shape->area() computes a circle's area for a Circle and a rectangle's for a Rectangle.

  • Compile-time polymorphism: function and operator overloading.
  • Run-time polymorphism: virtual functions.

Chapter 6 · Classes & Objects

Constructors & Destructors

Initialise objects automatically: default, parameterised and copy constructors, initialiser lists, constructor overloading, and destructors with the order they run in.

A constructor is a special member function that runs automatically when an object is created. Its job is to put the object into a valid starting state.

  • Same name as the class.
  • No return type — not even void.
  • Can be overloaded.

#Default and parameterised constructors

The compiler's free constructor disappears

If you write no constructors, the compiler supplies a default one. As soon as you write any constructor, it does not — so Student a; stops compiling unless you also write Student().

#Initialiser lists

The preferred way to initialise members is a member initialiser list, after a colon. It initialises members directly instead of assigning them afterwards, and it is required for const members, reference members and base classes.

#Copy constructor

The copy constructor creates a new object as a copy of an existing one. It takes a const reference to an object of the same class. It runs when you:

  1. initialise one object from another: Point b = a; or Point b(a);
  2. pass an object by value to a function;
  3. return an object by value (often optimised away).
Why must the copy constructor take a reference?

If it took its parameter by value, calling it would require copying the argument — which calls the copy constructor again, forever. Passing by reference breaks the infinite recursion.

#Destructors

A destructor runs automatically when an object is destroyed — when it goes out of scope, or when you delete it. Its name is the class name with a tilde: ~Student(). It takes no arguments, returns nothing, and cannot be overloaded. Use it to release resources: memory, files, network connections.

Objects are destroyed in the reverse order of construction — like a stack.

#Managing a resource: a dynamic array class

Without the copy constructor, b would share a's pointer (a shallow copy): changing b would change a, and both destructors would delete[] the same memory. More on this in Dynamic Memory & Smart Pointers.

Chapter 8 · Classes & Objects

Friend Functions & Classes

Grant selected functions or classes access to private members — when it is useful, how it works, and why to use it sparingly.

Private members are hidden from everything outside the class. Sometimes a function that is not a member genuinely needs that access — for example, a function that compares two objects of different classes, or an operator like << whose left side is cout. A class can declare such a function its friend.

#Friend function

Properties of a friend function:

  • It is declared inside the class with friend, but it is not a member — it is called like a normal function, volume(b), not b.volume().
  • It can access the class's private and protected members through an object.
  • The declaration can go in the public or private section; it makes no difference.

#A friend of two classes

A classic use: one function needs the private data of two classes.

#Friend class

A whole class can be a friend: all its member functions get access.

#Friendship rules

  1. Not mutual: if A declares B a friend, B can access A, but A cannot access B.
  2. Not inherited: a friend of the base class is not automatically a friend of derived classes.
  3. Not transitive: a friend of a friend is not a friend.
Use friends sparingly

Every friend weakens encapsulation. The most common legitimate use is overloading << and >> for your class — see Operator Overloading.

Chapter 9 · Inheritance & Polymorphism

Inheritance

Reuse and extend classes: base and derived classes, public/protected/private inheritance, the five types of inheritance, constructor order, and the diamond problem.

Inheritance lets a new class (the derived or child class) take on the members of an existing class (the base or parent class), then add its own or change some. It models an is-a relationship and avoids writing the same code twice.

#Access in derived classes

A derived class can use the base's public and protected members, but never its private ones. The mode of inheritance (public, protected, private) then decides how inherited members appear to the outside world:

Base member public inheritance protected inheritance private inheritance
public public protected private
protected protected protected private
private not accessible not accessible not accessible

public inheritance is by far the most common — it is the one that means "is-a".

Chapter 11 · Inheritance & Polymorphism

Virtual Functions & Runtime Polymorphism

Base-class pointers to derived objects, why virtual changes which function runs, override, virtual destructors, and how the vtable makes it work.

#The problem: static binding

A base-class pointer can point to a derived object. But by default, calling a function through it runs the base version — the compiler decides at compile time from the pointer's type. This is static (early) binding.

#The fix: virtual functions

Mark the base function virtual. Now the function is chosen at run time from the actual object — dynamic (late) binding. This is runtime polymorphism.

payslip() is written once in the base class, yet it calls the right pay() and role() for each object. Adding a new kind of employee requires no change to payslip — that is the real power of polymorphism.

Always write override

override (C++11) asks the compiler to check that you really are overriding a virtual function. A typo like double pay() without const would otherwise silently create a new, unrelated function.

#Virtual destructors

If you delete a derived object through a base pointer and the base destructor is not virtual, only the base destructor runs — the derived part leaks.

Rule

Any class meant to be used through base pointers should have a virtual destructor.

#How it works: the vtable

For each class with virtual functions, the compiler builds a virtual table (vtable): an array of pointers to that class's versions of the virtual functions. Each object gets a hidden pointer (the vptr) to its class's vtable. A virtual call follows object → vptr → vtable → function. That is one extra pointer lookup per call, and one extra pointer per object:

Static binding Dynamic binding
decided at compile time decided at run time
normal and overloaded functions virtual functions called through pointers/references
faster tiny overhead (vtable lookup)
also called early binding also called late binding
Object slicing

Polymorphism only works through pointers or references. Assigning a derived object to a base object (Employee e = m;) copies just the base part — the derived data is "sliced off" and e.pay() uses the base version.

Abstract Classes & Interfaces

Pure virtual functions, abstract base classes that cannot be instantiated, interfaces, and the final keyword — designing a clean class hierarchy.

#Pure virtual functions

Sometimes a base class cannot sensibly implement a function. What is the area of a generic "Shape"? Declare it pure virtual with = 0: it has no body in the base, and every concrete derived class must override it.

#Abstract classes

A class with at least one pure virtual function is an abstract class:

  • You cannot create objects of it: Shape s; is a compile error.
  • You can have pointers and references to it.
  • A derived class that does not override every pure virtual function is abstract too.

Exception Handling

Handle errors cleanly with try, throw and catch: standard exception classes, multiple and catch-all handlers, custom exceptions, and stack unwinding.

Programs meet errors at run time: division by zero, a missing file, bad input, memory exhaustion. Checking return codes everywhere clutters code and errors are easy to ignore. Exceptions separate error detection from error handling.

  • throw — signal an error.
  • try — wrap code that might throw.
  • catch — handle a specific kind of error.

#Standard exception classes

The standard library throws objects derived from std::exception. Each has a what() method returning a message.

#Stack unwinding

When an exception propagates out of functions, every local object on the way is destroyed properly — its destructor runs. This is why C++ resources should be owned by objects (RAII): cleanup happens automatically even on errors.

Chapter 15 · Beyond the Basics

Dynamic Memory & Smart Pointers

new and delete, arrays on the heap, shallow vs deep copy, the rule of three, and modern smart pointers — unique_ptr and shared_ptr — that free memory for you.

#new and delete

C++ replaces malloc/free with new and delete. new allocates memory and calls the constructor; delete calls the destructor and frees the memory.

malloc / free new / delete
function from <cstdlib> operator built into the language
returns void *, needs a cast returns the correct pointer type
size given in bytes size computed from the type
does not call constructors/destructors calls constructors and destructors
returns NULL on failure throws bad_alloc on failure
delete vs delete[]

Memory from new must be released with delete; memory from new[] with delete[]. Mixing them is undefined behaviour.

#Shallow copy vs deep copy

If a class owns heap memory through a pointer, the compiler's default copy copies the pointer, not the data — a shallow copy. Two objects then share one buffer, and both destructors free it: a crash.

A deep copy allocates new memory and copies the contents.

If a class needs a custom destructor, it almost certainly also needs a custom copy constructor and copy assignment operator:

#Smart pointers

Manual delete is easy to forget, especially when exceptions fly. Smart pointers in <memory> own heap objects and free them automatically — the RAII idea applied to memory.

Abstract class vs interface has some pure virtual functions vs only pure virtual functions
Pointer vs reference nullable, re-seatable vs always bound, alias
new/delete vs malloc/free calls constructors/destructors, type-safe, throws bad_alloc
Function template vs overloading one generic definition vs one definition per type
