Chapter 1 · Foundations

Introduction to Data Structures

What a data structure is, abstract data types, linear vs non-linear structures, and why choosing well matters more than coding fast.

A data structure is a way of organising data in memory so that the operations you need — search, insert, delete, find the smallest — are fast. The same million phone numbers can be stored in an array, a linked list, a tree or a hash table; each choice makes some operations quick and others slow.

Bad programmers worry about the code. Good programmers worry about data structures and their relationships. — Linus Torvalds

#Why it matters

Imagine looking up a contact among 1,000,000 numbers:

Structure Steps to find one number (worst case)
Unsorted array, linear search 1,000,000
Sorted array, binary search about 20
Hash table about 1

Same data, same computer — a 1,000,000× difference, purely from how the data is organised.

#Abstract data types

An abstract data type (ADT) describes what operations a structure supports, not how they are implemented. A data structure is a concrete implementation of an ADT.

ADT Operations Common implementations
List insert, delete, get(i), search array, linked list
Stack push, pop, peek array, linked list
Queue enqueue, dequeue, front circular array, linked list
Priority queue insert, extract-min/max binary heap
Map / dictionary put(key, value), get(key) hash table, balanced BST
Set add, remove, contains hash table, BST

Think of an ADT as a remote control's buttons, and the data structure as the electronics inside.

#Classifying data structures

  • Linear: elements form a sequence, each with at most one predecessor and successor — arrays, linked lists, stacks, queues.
  • Non-linear: an element can connect to many others — trees (hierarchies) and graphs (networks).
  • Static: size fixed at compile time (a C array).
  • Dynamic: grows and shrinks at run time (a linked list built with malloc).

#The operations we measure

Every structure in this course is judged by the cost of a handful of operations:

  1. Traversal — visit every element once.
  2. Search — find an element with a given key.
  3. Insertion — add an element.
  4. Deletion — remove an element.
  5. Sorting and merging — for collections of data.

The next lesson gives you the language for comparing those costs: Big-O notation.

Chapter 2 · Foundations

Time & Space Complexity

Count steps instead of seconds: Big-O notation, the common growth rates, analysing loops, and best, average and worst cases.

How do you compare two algorithms? Timing them with a stopwatch depends on the computer, the compiler and the input. Instead we count how the number of basic steps grows with the input size n. That growth rate is the algorithm's time complexity.

#Big-O notation

O(f(n)) describes an upper bound on growth, ignoring constants and smaller terms:

  • 3n² + 5n + 100 → O(n²) (n² dominates for large n)
  • 7n + 20 → O(n)
  • 500 → O(1)

We drop constants because we care about scaling: does doubling the input double the work, quadruple it, or barely change it?

#The growth rates you must know

Big-O Name Example n = 1,000
O(1) constant array index, hash lookup 1
O(log n) logarithmic binary search ~10
O(n) linear linear search, traversal 1,000
O(n log n) linearithmic merge sort, heap sort ~10,000
O(n²) quadratic bubble sort, nested loops 1,000,000
O(2ⁿ) exponential naive Fibonacci, all subsets ~10³⁰⁰
O(n!) factorial all permutations unimaginable

The "triangle" loop does n(n−1)/2 steps — about half of n², but still O(n²), because constants are dropped.

#Rules of thumb

  1. Sequential steps add: O(n) followed by O(n²) is O(n + n²) = O(n²).
  2. Nested loops multiply: an O(n) loop inside an O(n) loop is O(n²).
  3. Drop constants and lower terms: O(2n + 10) = O(n).
  4. Halving or doubling the remaining work each step gives O(log n).
  5. Different inputs keep different letters: looping over n items then m items is O(n + m), not O(n).

#Best, average and worst case

The same algorithm can take different time on different inputs of the same size. For linear search on n items:

  • Best case: the key is first — 1 comparison, O(1).
  • Worst case: the key is last or absent — n comparisons, O(n).
  • Average case: about n/2 comparisons — still O(n).

We usually quote the worst case, because it is a guarantee.

#Space complexity

Space complexity measures extra memory used as n grows. Reversing an array in place uses O(1) extra space; copying it into a new array uses O(n). A recursive function uses stack space proportional to its maximum recursion depth.

Ω and Θ

Big-O is an upper bound. Ω (omega) is a lower bound and Θ (theta) is a tight bound (both upper and lower). The Asymptotic Notations lesson in Algorithms covers them formally.

Chapter 3 · Foundations

Arrays as a Data Structure

Arrays from the data-structure point of view: O(1) access, the cost of insertion and deletion by shifting, and when an array is the right choice.

You already know how to use arrays from the C course. Here we look at them as a data structure: what each operation costs.

An array stores elements in contiguous memory. Because every element has the same size, the address of a[i] is simply base + i × size. That makes access O(1) — the computer jumps straight there.

#Insertion at a position

To insert at index pos, every element from pos onwards must shift one place right to make room. Inserting at the front of n elements moves all n: O(n).

#Deletion at a position

Deleting shifts the later elements left to close the gap: also O(n) in the worst case.

Delete in O(1) when order does not matter

If the order of elements is not important, copy the last element into the deleted slot and shrink the size by one. No shifting needed.

#Array operation costs

Operation Cost Why
Access a[i] O(1) address arithmetic
Update a[i] = x O(1) address arithmetic
Search (unsorted) O(n) may check every element
Search (sorted) O(log n) binary search
Insert / delete at end O(1) nothing to shift
Insert / delete at front or middle O(n) shifting

#Strengths and weaknesses

Use an array when you need fast random access by index, the size is known or changes rarely, and you mostly add or remove at the end.

Avoid an array when you insert and delete in the middle a lot, or the size is completely unpredictable — that is where linked lists shine.

Cache friendliness

Because array elements sit next to each other, the CPU loads several of them into its cache at once. In practice, traversing an array is often several times faster than traversing a linked list with the same Big-O.

#Merging two sorted arrays

A pattern you will reuse in merge sort: walk both arrays with two indexes, always taking the smaller front element. It runs in O(n + m).

Chapter 4 · Linked Lists

Singly Linked List

Nodes joined by pointers: create, traverse, insert at the head, tail or a position, delete, and search — with every operation's cost.

A linked list stores elements in separate nodes scattered around memory. Each node holds its data and a pointer to the next node. The list is reached through a pointer to the first node, called the head; the last node points to NULL.

Unlike an array, a linked list can grow one node at a time and insert anywhere without shifting other elements — you only rewire pointers.

#The node

A structure that contains a pointer to its own type is called self-referential.

#Try it

Insert and delete nodes and watch the pointers change:

#The complete program

Every function receives Node **head (a pointer to the head pointer) when it may need to change which node is first.

#Inserting in the middle, step by step

To insert 25 after node 20:

  1. Create the new node: n->data = 25.
  2. Point it at the rest of the list: n->next = p->next; (25 → 30).
  3. Point 20 at it: p->next = n; (20 → 25).
Order matters

If you do step 3 before step 2, p->next already points at the new node, and the link to 30 (and everything after it) is lost forever.

#Deleting a node

Find the node and the one before it, make the previous node skip over it, then free it. Deleting the head is a special case: move head forward.

#Costs: array vs linked list

Operation Array Singly linked list
Access the i-th element O(1) O(n)
Insert / delete at the front O(n) O(1)
Insert / delete at the end O(1) O(n), or O(1) with a tail pointer
Insert / delete after a known node O(n) O(1)
Search O(n) O(n)
Extra memory none one pointer per node
Memory layout contiguous, cache-friendly scattered
Advantages and disadvantages

Advantages: dynamic size, O(1) insertion/deletion once you have the position, no wasted capacity. Disadvantages: no random access (no binary search), extra memory for pointers, poor cache performance, can only be traversed forwards.

Chapter 6 · Linked Lists

Doubly & Circular Linked Lists

Lists that go both ways or loop around: node structure, insertion and deletion in a doubly linked list, circular lists, and when to use each.

#Doubly linked list

Each node in a doubly linked list has two pointers: prev and next. You can walk in both directions, and you can delete a node when you only have a pointer to it.

When inserting in the middle of a doubly linked list, four pointers change: the new node's prev and next, the previous node's next and the following node's prev.

#Circular linked list

In a circular list, the last node points back to the first instead of NULL. There is no natural end, so traversal stops when you return to the starting node. It is often accessed through a pointer to the last node, because last->next is the first node — giving O(1) insertion at both ends.

Where circular lists are used

Round-robin CPU scheduling (each process gets a turn, forever), multiplayer turn order, music playlists on repeat, and circular buffers in device drivers.

#Which list should you use?

Singly Doubly Circular
Pointers per node 1 2 1 (or 2 if doubly circular)
Traverse backwards no yes no
Delete a node given only its pointer no (needs previous) O(1) no
Memory least most least
Natural use stacks, simple lists browser history, LRU caches, text editors round-robin, repeating playlists

Stack

Last in, first out: push, pop and peek, overflow and underflow, and two implementations — with an array and with a linked list.

A stack is a collection where you can only add or remove at one end, called the top. The last item pushed is the first one popped: LIFO (Last In, First Out). Think of a pile of plates, the browser Back button, or Undo in a text editor.

#Operations

Operation Meaning Cost

pop() remove and return the top item O(1)
peek() / top() look at the top item without removing it O(1)
isEmpty() is the stack empty? O(1)
isFull() (array version) is it at capacity? O(1)

Pushing onto a full array stack is overflow; popping from an empty stack is underflow.

  • Undo/redo and the browser Back button.

Chapter 8 · Stacks & Queues

Stack Applications

Balanced brackets, infix to postfix conversion and postfix evaluation — the three stack algorithms every CSE 102 exam asks you to trace.

#1. Balanced brackets

Every opening bracket must be closed by the matching bracket in the right order. Push each opener; on each closer, pop and check it matches.

#Infix, prefix and postfix

Notation Operator position A + B * C Needs brackets?
Infix between operands A + B * C yes, plus precedence rules
Prefix (Polish) before operands + A * B C no
Postfix (Reverse Polish) after operands A B C * + no

Computers prefer postfix: it can be evaluated left to right with one stack and no precedence rules.

#2. Infix to postfix (shunting-yard)

Scan the infix expression left to right:

  1. Operand → write it to the output.
  2. ( → push it.
  3. ) → pop to the output until the matching (; discard both brackets.
  4. Operator → while the stack top is an operator of higher precedence, or equal precedence and left-associative, pop it to the output. Then push the new operator.
  5. At the end, pop everything left to the output.

Precedence: ^ (highest, right-associative) > * / > + -.

#Tracing A+B*C-D/E

Symbol Action Stack Output
A output A
+ push + A
B output + AB
* higher than +, push + * AB
C output + * ABC
- pop * and + (≥ precedence), push - - ABC*+
D output - ABC*+D
/ higher than -, push - / ABC*+D
E output - / ABC*+DE
end pop all ABC*+DE/-
How to score full marks

Draw exactly this three-column table (symbol, stack, postfix) for every step. Examiners award most of the marks for the trace, not just the final answer.

#3. Evaluating postfix

Scan left to right. Push numbers. On an operator, pop two values — the first pop is the right operand — apply the operator and push the result.

Trace of 2 3 1 * + 9 -: push 2, 3, 1 → * pops 1 and 3, pushes 3 → + pops 3 and 2, pushes 5 → push 9 → - pops 9 and 5, pushes 5 − 9 = −4.

Operand order

For - and /, order matters. With postfix 6 2 /, the first value popped (2) is the right operand: 6 / 2 = 3, not 2 / 6.

#Prefix evaluation

Prefix works the same way but scanning right to left, and the first value popped is the left operand. Example: - + 2 * 3 1 9 evaluates to (2 + 3 × 1) − 9 = −4.

Chapter 9 · Stacks & Queues

Queue & Circular Queue

First in, first out: enqueue and dequeue, why a simple array queue wastes space, and how the circular queue fixes it — plus a linked-list queue.

A queue adds at one end (the rear) and removes from the other (the front): FIFO — First In, First Out. It models every real queue: people at a ticket counter, print jobs, network packets, processes waiting for the CPU.

Operation Meaning Cost
enqueue(x) add x at the rear O(1)
dequeue() remove and return the front item O(1)
front() / peek() look at the front item O(1)
isEmpty(), isFull() status checks O(1)

#The problem with a simple array queue

Use front and rear indexes into an array. Enqueue does a[++rear] = x; dequeue does front++. But after a few dequeues, the empty slots at the start of the array are never reused: the queue reports "full" when rear reaches the end, even if it is mostly empty.

#Circular queue

The fix: let the indexes wrap around to 0 using % capacity. The array behaves like a ring.

  • enqueue: rear = (rear + 1) % N; a[rear] = x;
  • dequeue: x = a[front]; front = (front + 1) % N;
  • keep a count to tell full from empty.
Without a count variable

Many textbooks leave one slot empty instead: the queue is empty when front == rear and full when (rear + 1) % N == front. Both approaches are correct — know whichever your teacher uses.

#Linked-list queue

Keep pointers to both ends: enqueue at the tail, dequeue at the head. Both are O(1), and there is no fixed capacity.

#Stack vs queue

Stack Queue
Order LIFO FIFO
Insert at top rear
Remove from top front
Typical uses undo, recursion, DFS, parsing scheduling, buffering, BFS

Chapter 11 · Trees

Trees & Binary Trees

Hierarchical data: tree vocabulary, types of binary trees, array and linked representations, and the four traversals — inorder, preorder, postorder and level order.

A tree stores data in a hierarchy: one root at the top, and every other node has exactly one parent. File systems, the HTML of a web page, an organisation chart and a family tree are all trees.

#Vocabulary

Term Meaning (for the tree above)
Root the top node with no parent — A
Parent / child B is the parent of D and E
Siblings nodes with the same parent — D and E
Leaf a node with no children — D, E, F, G
Internal node a node with at least one child — A, B, C
Edge a link between parent and child (a tree with n nodes has n − 1 edges)
Depth of a node edges from the root to it — depth(D) = 2
Height of a tree edges on the longest root-to-leaf path — 2 here
Degree of a node number of children — degree(A) = 2
Subtree a node together with all its descendants

#Binary trees

A binary tree is a tree where each node has at most two children, called left and right.

Type Definition
Full (strict) every node has 0 or 2 children
Perfect full, and all leaves at the same level: 2ʰ⁺¹ − 1 nodes
Complete every level full except possibly the last, which is filled left to right
Skewed every node has only one child — basically a linked list
Balanced heights of left and right subtrees differ by at most 1 at every node
Formulas worth memorising
  • Maximum nodes at level l = 2ˡ (root is level 0).
  • Maximum nodes in a binary tree of height h = 2ʰ⁺¹ − 1.
  • Minimum height with n nodes = ⌈log₂(n + 1)⌉ − 1.
  • In a full binary tree, leaves = internal nodes + 1.

#Representing a binary tree

Linked representation — each node holds data plus left and right pointers:

Array representation — store level by level. For the node at index i (0-based): left child at 2i + 1, right child at 2i + 2, parent at (i − 1) / 2. Perfect for complete trees (like heaps); wasteful for skewed ones.

#Traversals

A traversal visits every node once. Depth-first traversals differ only in when you visit the node relative to its subtrees:

Traversal Order Result for the tree above
Preorder Node, Left, Right A B D E C F G
Inorder Left, Node, Right D B E A F C G
Postorder Left, Right, Node D E B F G C A
Level order level by level, left to right (uses a queue) A B C D E F G
A quick way to write traversals by hand

Trace a line around the tree, starting left of the root and hugging every node. Preorder lists a node when you pass its left side, inorder when you pass underneath it, postorder when you pass its right side.

#Rebuilding a tree from traversals

Given inorder + preorder (or inorder + postorder), the tree is unique:

  1. The first preorder element (or last postorder element) is the root.
  2. Find the root in the inorder sequence: everything to its left is the left subtree, everything to its right is the right subtree.
  3. Repeat for each subtree.

Preorder + postorder alone is not enough unless the tree is full.

Chapter 12 · Trees

Binary Search Tree

A binary tree that keeps itself sorted: search, insert, find min and max, and the three cases of deletion — plus why balance matters.

A binary search tree (BST) is a binary tree with one rule at every node:

All keys in the left subtree are smaller, and all keys in the right subtree are larger.

Because of that rule, an inorder traversal of a BST prints the keys in sorted order, and searching can discard half the remaining tree at each step — like binary search.

#Try it

#Search and insert

To search, start at the root: go left if the key is smaller, right if it is larger, stop if equal. Insertion searches for the key and attaches a new leaf where the search fell off the tree.

#Minimum and maximum

The smallest key is the leftmost node; the largest is the rightmost:

#Deletion: three cases

  1. Leaf — just remove it.
  2. One child — replace the node with its child.
  3. Two children — replace the node's key with its inorder successor (the smallest key in its right subtree), then delete that successor from the right subtree. (The inorder predecessor works too.)

After deleting 50, its inorder successor 60 takes its place as the new root.

#Why balance matters

Every BST operation costs O(h), where h is the height.

  • A balanced BST with n keys has height about log₂ n → operations are O(log n).
  • Insert keys in sorted order (10, 20, 30, 40…) and every new key goes right: the tree becomes a skewed chain with height n − 1 → O(n), no better than a linked list.

That is why self-balancing trees such as AVL trees (next lesson) and red-black trees exist.

Operation Balanced BST Skewed BST
Search O(log n) O(n)
Insert O(log n) O(n)
Delete O(log n) O(n)
Inorder traversal O(n) O(n)

Chapter 13 · Trees

AVL Trees

Self-balancing BSTs: balance factors, the four rotation cases (LL, RR, LR, RL), and an insertion that stays O(log n) whatever order the keys arrive in.

An AVL tree (named after Adelson-Velsky and Landis, 1962) is a BST that keeps itself balanced. After every insertion or deletion it checks each node's balance factor and fixes any imbalance with rotations.

#Balance factor

balance factor = height(left subtree) − height(right subtree)

In an AVL tree, every node's balance factor must be −1, 0 or +1. If an insertion makes some node's balance factor +2 or −2, that node is rebalanced. This keeps the height at most about 1.44 log₂ n, so search, insert and delete are all O(log n) guaranteed.

#The four imbalance cases

Let Z be the lowest unbalanced node on the path from the inserted key up to the root.

Case Inserted into Fix
LL left subtree of Z's left child one right rotation at Z
RR right subtree of Z's right child one left rotation at Z
LR right subtree of Z's left child left rotation at the child, then right rotation at Z
RL left subtree of Z's right child right rotation at the child, then left rotation at Z

#LL case: right rotation

Inserting 30, 20, 10 makes 30 left-heavy (balance factor +2):

Rotate right at 30: the left child 20 moves up to become the root, 30 moves down to become 20's right child, and 20's old right subtree (empty here) becomes 30's new left subtree.

#RR case: left rotation

Inserting 10, 20, 30 is the mirror image: rotate left at 10 and 20 becomes the root.

#LR case: double rotation

Inserting 30, 10, 20: the imbalance is at 30 (left-heavy), but the new key went into the right of the left child. A single right rotation would not fix it. First rotate left at 10 (turning it into the LL case), then rotate right at 30. The result is again 20 with children 10 and 30.

Chapter 14 · Trees

Heaps & Heap Sort

Complete binary trees stored in arrays: max-heaps and min-heaps, insert with sift-up, extract with sift-down, building a heap in O(n), and heap sort.

A binary heap is a complete binary tree with the heap property:

  • Max-heap: every parent ≥ its children, so the largest key is at the root.
  • Min-heap: every parent ≤ its children, so the smallest key is at the root.

Unlike a BST, a heap says nothing about left versus right — only parent versus child.

#Stored in an array

Because a heap is complete, it fits perfectly in an array with no gaps — no pointers needed. For index i (0-based): parent (i − 1) / 2, left child 2i + 1, right child 2i + 2.

#Insert: add at the end, then sift up

Put the new key in the next free slot (keeping the tree complete), then swap it with its parent while it is larger. At most one swap per level: O(log n).

#Extract max: move the last key to the root, then sift down

Remove the root (the maximum). Move the last element to the root, then swap it with its larger child while it is smaller than that child. Also O(log n).

#Building a heap in O(n)

Inserting n keys one by one costs O(n log n). Heapify does better: start from the last internal node (index n/2 − 1) and sift each node down, moving towards the root. Most nodes are near the bottom and sift down only a little, which adds up to O(n).

#Heap sort

  1. Build a max-heap from the array — O(n).
  2. Repeatedly swap the root (maximum) with the last element of the heap, shrink the heap by one, and sift the new root down — n × O(log n).

Total O(n log n) in every case, using O(1) extra space. It is not stable.

#Heap operation costs

Operation Cost
Find max (max-heap) O(1)
Insert O(log n)
Extract max O(log n)
Build heap from n keys O(n)
Heap sort O(n log n)

Heaps are the standard way to implement priority queues — used in Dijkstra's shortest paths, Prim's MST, CPU scheduling and "top-k" problems.

Graphs: Terminology & Representation

Vertices and edges: directed, weighted and connected graphs, degree, paths and cycles, and storing graphs as adjacency matrices and adjacency lists.

A graph G = (V, E) is a set of vertices (nodes) V connected by edges E. Graphs model anything with connections: road maps, social networks, the web, course prerequisites, computer networks.

#Vocabulary

Term Meaning
Undirected graph edges have no direction: A–B means both ways
Directed graph (digraph) edges are arrows: A → B does not imply B → A
Weighted graph each edge carries a number (distance, cost, time)
Adjacent two vertices joined by an edge
Degree number of edges at a vertex; in digraphs, in-degree and out-degree
Path a sequence of vertices joined by edges
Cycle a path that starts and ends at the same vertex
Connected there is a path between every pair of vertices
Tree a connected graph with no cycles (n vertices, n − 1 edges)
DAG directed acyclic graph — a digraph with no directed cycles
Handshake lemma

In any undirected graph, the sum of all degrees is twice the number of edges, because each edge adds 1 to the degree of both ends. In the graph above: 2 + 3 + 2 + 3 + 2 = 12 = 2 × 6. A consequence: the number of odd-degree vertices is always even.

#Directed and weighted graphs

#Representation 1: adjacency matrix

A V × V grid where adj[i][j] = 1 (or the weight) if there is an edge from i to j.

  • Check "is there an edge i–j?" in O(1).
  • Uses O(V²) memory even if there are few edges.
  • Listing a vertex's neighbours takes O(V).

#Representation 2: adjacency list

An array of lists: adj[i] holds the neighbours of vertex i.

  • Uses O(V + E) memory — ideal for sparse graphs (most real graphs).
  • Listing neighbours is fast: O(degree).
  • Checking a specific edge takes O(degree).

(The list shows neighbours in reverse insertion order because each new edge is added at the head of the list.)

#Matrix or list?

Adjacency matrix Adjacency list
Memory O(V²) O(V + E)
Is (u, v) an edge? O(1) O(deg(u))
Visit all neighbours of u O(V) O(deg(u))
Best for dense graphs, quick edge checks sparse graphs, traversals

Chapter 16 · Graphs & Hashing

Graph Traversal: BFS & DFS

Explore a graph level by level with a queue (BFS) or as deep as possible with a stack or recursion (DFS) — with step-by-step traces, shortest paths and applications.

To traverse a graph is to visit every vertex reachable from a starting vertex. Unlike a tree, a graph can have cycles, so we keep a visited array to avoid looping forever.

#Breadth-first search (BFS)

BFS visits the start, then all its neighbours, then all their unvisited neighbours — expanding outward in rings, like ripples in water. It uses a queue.

  1. Mark the start visited and enqueue it.
  2. While the queue is not empty: dequeue a vertex, visit it, and enqueue each unvisited neighbour (marking it visited).

#Depth-first search (DFS)

DFS goes as deep as possible along one path before backtracking. It uses a stack — usually the call stack, via recursion.

  1. Visit the vertex and mark it visited.
  2. For each unvisited neighbour, recursively DFS from it.

BFS DFS

#Applications

  • Connected components: run DFS/BFS from every unvisited vertex; each run discovers one component.
  • Cycle detection: in DFS, reaching a visited vertex that is not your parent means a cycle (undirected graphs).
  • Topological sort of a DAG: output vertices in reverse order of DFS completion — see Graph Algorithms.
  • Bipartite check: BFS-colour vertices in two colours; a conflict means not bipartite.
Forgetting visited marks

Without the visited array, BFS and DFS loop forever on any graph with a cycle — and even on a single undirected edge, which goes both ways.

Chapter 17 · Graphs & Hashing

Hashing

Near O(1) search with hash tables: hash functions, collisions, separate chaining, linear and quadratic probing, double hashing and the load factor.

Arrays give O(1) access by index. What if you could turn any key — a roll number, a name — into an index? That is hashing: a hash function converts a key into an index of an array called a hash table.

Search, insert and delete then take O(1) on average.

#Good hash functions

A good hash function is fast, deterministic, and spreads keys uniformly over the table.

Method Formula Notes
Division h(k) = k mod m choose m prime, away from powers of 2
Multiplication h(k) = ⌊m × frac(k × A)⌋, 0 < A < 1 m can be anything
Mid-square square k, take the middle digits old textbook method
Folding split k into parts and add them for long keys like phone numbers
Strings h = h × 31 + c for each character how Java hashes strings

#Collisions

Two keys can hash to the same slot: with m = 10, both 23 and 33 go to slot 3. That is a collision, and every hash table needs a strategy for it.

#Separate chaining

Each slot holds a linked list of all keys that hash there.

#Open addressing

All keys live inside the array. On a collision, probe other slots in a fixed sequence until an empty one is found.

Probing Try slots Weakness
Linear h, h+1, h+2, … (mod m) primary clustering — long runs of filled slots
Quadratic h, h+1², h+2², h+3², … secondary clustering; may miss empty slots
Double hashing h, h + h₂(k), h + 2·h₂(k), … best spread; needs h₂(k) ≠ 0

Deleting with open addressing

You cannot simply empty a slot: a later search would stop at the hole and miss keys that probed past it. Mark deleted slots with a special tombstone value instead.

#Load factor and rehashing

The load factor α = n / m (keys stored ÷ table size) measures how full the table is.

  • Chaining: average chain length is α, so keep α around 1.
  • Open addressing: performance falls sharply as α approaches 1; keep α below about 0.7.
  • When α gets too high, rehash: allocate a table about twice the size and reinsert every key.

#Costs

Average Worst case
Search / insert / delete O(1) O(n) — everything collides

Hash tables power dictionaries in Python, unordered_map in C++, database indexes, caches and compilers' symbol tables.

Chapter 18 · Searching & Sorting

Linear & Binary Search

Find things fast: linear search for any list, binary search for sorted ones — iterative and recursive versions, step-by-step traces and the classic off-by-one traps.

#Linear search

Check every element from the start until you find the key. It works on any list, sorted or not.

  • Best case O(1), worst and average case O(n).

You wrote it in the Arrays lesson. Its weakness is speed on large data.

#Binary search

If the array is sorted, you can do much better. Look at the middle element:

  • equal to the key → found;
  • key smaller → the key can only be in the left half;
  • key larger → it can only be in the right half.

Each step halves the search space, so at most about log₂ n steps are needed: O(log n). For a million elements that is 20 comparisons instead of a million.

#Iterative binary search

#Recursive binary search

Recurrence: T(n) = T(n/2) + O(1) → O(log n). The recursive version uses O(log n) stack space; the iterative one uses O(1).

Binary search bugs
  • Using it on an unsorted array — it silently gives wrong answers.
  • while (low < high) instead of <= — misses single-element ranges.
  • low = mid or high = mid instead of mid ± 1 — can loop forever.
  • (low + high) / 2 can overflow for huge arrays; low + (high - low) / 2 cannot.

#Variants worth knowing

Binary search finds more than exact matches. Changing what happens on equality gives you the first or last occurrence of a repeated key:

Linear search Binary search
Needs sorted data no yes
Time O(n) O(log n)
Works on linked lists yes not efficiently (no random access)

Bubble, Selection & Insertion Sort

The three O(n²) sorts: how each one works, passes and swaps traced by hand, stability, best cases, and when a simple sort is the right choice.

Sorting puts elements in order. Sorted data makes searching (binary search), finding duplicates, merging and reporting much easier. We start with three simple sorts that are easy to trace by hand — exactly what exams ask.

Watch them run on the same data:

#Bubble sort

Compare adjacent pairs and swap if they are in the wrong order. After pass 1 the largest element has "bubbled" to the end; after pass 2, the second largest; and so on. If a pass makes no swaps, the array is already sorted and we can stop early.

#Selection sort

Find the minimum of the unsorted part and swap it to the front of that part. Exactly n − 1 swaps — useful when writing to memory is expensive.

#Insertion sort

Build the sorted part one element at a time: take the next element (the key) and shift larger sorted elements right until the key's place is found — the way you sort playing cards in your hand.

On nearly sorted data, insertion sort barely shifts anything and runs in close to O(n) — which is why fast library sorts switch to insertion sort for small pieces.

#Comparison

Bubble Selection Insertion
Best case O(n) (with early exit) O(n²) O(n)
Average / worst O(n²) O(n²) O(n²)
Swaps / writes many n − 1 swaps many shifts
Extra space O(1) O(1) O(1)
Stable? yes no yes
Adaptive (faster on sorted input)? yes no yes
Stable sort

A sorting algorithm is stable if equal elements keep their original relative order. It matters when sorting records by one field after another — for example by marks, keeping students with equal marks in roll-number order.

Chapter 20 · Searching & Sorting

Merge, Quick & Counting Sort

Faster sorting: divide-and-conquer merge sort and quick sort with their partition traces, plus counting and radix sort that beat O(n log n) on integers.

The O(n²) sorts are fine for a few hundred elements. For a million, you need O(n log n). Both merge sort and quick sort get there with divide and conquer: split the problem, solve the pieces recursively, combine.

#Merge sort

  1. Divide the array into two halves.
  2. Conquer: sort each half recursively.
  3. Combine: merge the two sorted halves (the two-pointer merge from the Arrays lesson).

Recurrence: T(n) = 2T(n/2) + O(n) → O(n log n) in every case. The merge needs an O(n) temporary array. Merge sort is stable and is the standard choice for sorting linked lists and huge files on disk.

#Quick sort

  1. Pick a pivot element.
  2. Partition: rearrange so everything smaller than the pivot is on its left and everything larger on its right. The pivot is now in its final position.
  3. Recursively sort the left and right parts. No merge step is needed.

The Lomuto partition uses the last element as the pivot:

Case When Cost
Best / average pivot splits roughly in half O(n log n)
Worst pivot is always the smallest or largest (e.g. sorted input with last-element pivot) O(n²)

Choosing a random pivot or the median of three makes the worst case extremely unlikely. In practice quick sort is often the fastest comparison sort: it sorts in place (O(log n) stack space) and is cache-friendly. It is not stable.

#Counting sort

When keys are small integers in a known range 0…k, you do not need comparisons at all. Count how many times each value occurs, then write the values out in order: O(n + k).

Radix sort applies a stable counting sort digit by digit (units, then tens, then hundreds…), sorting d-digit numbers in O(d × (n + 10)).

#The big comparison

Insertion O(n) O(n²) O(n²) O(1) yes
Merge O(n log n) O(n log n) O(n log n) O(n) yes

The O(n log n) barrier

Any sort that only compares elements needs Ω(n log n) comparisons in the worst case. Counting and radix sort beat it because they do not compare — they use the keys as array indexes.
