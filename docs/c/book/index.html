Chapter 1 · Getting Started

C Introduction

What C is, why it still runs the world, and your very first program — explained line by line.

C is a general-purpose programming language created by Dennis Ritchie at Bell Labs in 1972. It was built to write the Unix operating system, and today it still runs underneath almost everything: Linux and Windows kernels, Python's interpreter, databases like MySQL, microcontrollers in washing machines and cars.

C is small, fast and close to the hardware. You decide where every byte of memory goes. That makes it the perfect first language for a computer science student: once you understand C, every other language makes more sense.

Why CSE 101 starts with C

C hides almost nothing. You will see how numbers are stored, how memory is laid out and what a function call really costs — ideas that Data Structures (CSE 102), C++ and Operating Systems build on directly.

Chapter 2 · Getting Started

Syntax, Output & Comments

The grammar rules of C, how printf prints text and numbers, escape sequences, and how to comment code.

#C syntax rules

C is strict about grammar. Five rules cover almost every beginner error:

  1. Every statement ends with a semicolon ;.
  2. C is case-sensitive — printf works, Printf does not.
  3. Blocks use curly braces { }.
  4. Whitespace is ignored — indent for humans, not for the compiler.
  5. Text goes in double quotes "..."; a single character goes in single quotes 'A'.

Chapter 3 · Getting Started

Variables, Data Types & Constants

Store values in variables, choose the right data type, print them with the right format specifier, and lock values with constants.

A variable is a named box in memory that holds a value. Every variable in C has a type, which decides how many bytes the box uses and what kind of value it can hold.

#Declaring and naming variables

Naming rules (these are called identifiers):

  • Use letters, digits and underscores only: total_marks, num1.
  • Must not start with a digit: 1num is invalid.
  • Cannot be a keyword such as int, return, while.
  • Case matters: Sum and sum are different variables.
Always initialise

A local variable that you declare but never assign holds garbage — whatever bytes were already in that memory. Reading it gives unpredictable results. Get into the habit of writing int sum = 0;.

Chapter 5 · Getting Started

Operators & Expressions

Arithmetic, increment, relational, logical, bitwise and ternary operators — plus precedence and type casting, which examiners love.

Operators are symbols that perform operations on values (called operands). a + b uses the + operator on operands a and b.

#Arithmetic operators

Operator Meaning Example Result
+ Addition 17 + 5 22
- Subtraction 17 - 5 12
* Multiplication 17 * 5 85
/ Division 17 / 5 3 (integer division!)
% Remainder (modulus) 17 % 5 2
Integer division surprises

5 / 2 is 2, not 2.5, because both operands are int. And % only works on integers — 5.5 % 2 is a compile error (use fmod from math.h).

#Increment and decrement

++ adds 1 and -- subtracts 1. The position matters when the result is used in the same expression:

  • Pre-increment ++x: increase first, then use the new value.
  • Post-increment x++: use the old value, then increase.
Undefined behaviour

Expressions like i = i++ + ++i; change the same variable twice without a sequence point. The C standard says the result is undefined — different compilers print different answers. If an exam asks, say exactly that.

#Assignment operators

x += 3 is shorthand for x = x + 3. The same works for -=, *=, /=, %=, &=, |=, ^=, <<= and >>=.

#Relational and logical operators

Relational operators compare values and produce 1 (true) or 0 (false): ==, !=, <, >, <=, >=.

Logical operators combine conditions:

Operator Name True when
&& AND both sides are true
|| OR at least one side is true
! NOT the operand is false

C uses short-circuit evaluation: in a && b, if a is false, b is never evaluated. In a || b, if a is true, b is skipped. This lets you write safe checks like if (d != 0 && n / d > 2).

#Bitwise operators

Bitwise operators work on the individual bits of integers. They are fast and appear in systems code and interviews.

If, Else & Switch

Make decisions with if, else if, nested conditions and switch — with the classic grade, leap-year and calculator programs.

Programs become useful when they can decide. C runs a block of code only when a condition is true (any non-zero value) and skips it when the condition is false (zero).

#if

The braces can be dropped when the block has exactly one statement, but keeping them avoids bugs when you later add a second line.

#if...else

#else if ladders

Check conditions top to bottom; the first true one wins and the rest are skipped.

#Nested if: the leap-year program

A year is a leap year if it is divisible by 4, except century years, which must be divisible by 400. This is one of the most-asked programs in CSE 101 exams.

The same logic fits in one condition: (year % 4 == 0 && year % 100 != 0) || year % 400 == 0.

= is not ==

if (x = 5) assigns 5 to x and is always true. To compare, write if (x == 5). Many programmers write if (5 == x) so that a missing = becomes a compile error.

#switch

When you compare one integer or character against many fixed values, switch is cleaner than a long else if ladder:

Rules to remember:

  • The switch expression must be an integer type (int, char, enum) — not float or a string.
  • Each case label must be a constant, and labels must be unique.
  • break exits the switch. Without it, execution falls through into the next case.
  • default runs when no case matches. It is optional and can appear anywhere.

#while

A while loop checks its condition before each pass. Use it when you do not know in advance how many times to repeat.

A do-while loop checks its condition after each pass, so the body always runs at least once. That makes it perfect for menus:

#for

A for loop packs the three parts of counting into one line: initialise; condition; update.

Off-by-one and infinite loops

for (i = 0; i <= 10; i++) runs 11 times, not 10. And a loop whose condition never becomes false — like while (n > 0) without changing n — runs forever. In the playground, a runaway program is stopped automatically.

Chapter 9 · Functions

Functions

Split programs into named, reusable pieces: declarations, definitions, parameters, return values and call by value.

A function is a named block of code that does one job. You have been calling functions since lesson one — printf and scanf are functions written by someone else. Now you will write your own.

Why bother?

  • Reuse — write the logic once, call it many times.
  • Readability — isPrime(n) explains itself; forty lines of loop do not.
  • Testing — a small function is easy to check on its own.

A function is recursive when it calls itself. Recursion solves a problem by solving a smaller version of the same problem, until it reaches a case so small that the answer is obvious.

Every recursive function needs two parts:

  1. Base case — the smallest input, answered directly without recursion.
  2. Recursive case — express the answer using the same function on a smaller input.

Write the recurrence

Examiners often ask for the recurrence relation of a recursive function. For factorial: T(n) = T(n−1) + O(1), which solves to O(n). For naive Fibonacci: T(n) = T(n−1) + T(n−2) + O(1), which grows exponentially.

A 2D array is an array of arrays — a grid with rows and columns. It is how C represents matrices, game boards, seating charts and images.

Memory is one long line, so C stores 2D arrays in row-major order: all of row 0, then all of row 1, and so on. Element m[i][j] lives at position i * COLS + j from the start. That is why, when you pass a 2D array to a function, you must give the column count: void print(int m[][4], int rows).

Chapter 15 · Pointers & Memory

Pointers

Addresses, the & and * operators, pointer types, NULL, and pointer arithmetic — the idea that makes C powerful.

Every variable lives at some address in memory, like a house number. A pointer is a variable that stores an address. That one idea lets C build linked lists, pass big data without copying it, and talk directly to hardware.

#& and *

  • &x — the address-of operator: "where does x live?"
  • *p — the dereference operator: "the value stored at the address in p".

Addresses change every run, so your output will show different hex numbers. The picture below uses simple made-up addresses:

#Declaring pointers

The type before * says what the pointer points to:

All pointers are the same size (8 bytes on a 64-bit machine) because they all hold an address. The type matters for dereferencing and arithmetic.

#NULL and wild pointers

A pointer that has not been given an address yet should be set to NULL (address 0). Dereferencing NULL crashes the program immediately — which is much better than a wild pointer (uninitialised) that silently corrupts random memory.

The three pointer bugs
  • Wild pointer: int *p; *p = 5; — p holds a garbage address.
  • NULL dereference: int *p = NULL; printf("%d", *p); — crash.
  • Dangling pointer: pointing at memory that no longer exists, such as a local variable of a function that has returned, or memory you already freed.

#Pointer arithmetic

Adding 1 to a pointer moves it to the next element, not the next byte. For an int * (4-byte ints), p + 1 is 4 bytes further on.

Allowed pointer operations: add or subtract an integer, subtract two pointers into the same array, and compare pointers. You cannot add, multiply or divide two pointers.

An array's name, used in an expression, decays to a pointer to its first element. These are all equivalent:

Array notation Pointer notation
a[i] *(a + i)
&a[i] a + i
a[0] *a

(2[a] works because a[i] is defined as *(a + i), and addition does not care about order. Fun fact, never write it in real code.)

An array is not a pointer

They behave alike in expressions, but: sizeof(a) gives the whole array's size while sizeof(p) gives 8; and a = p; is illegal because an array name is not a variable you can reassign.

Ask for memory at run time with malloc, calloc and realloc, give it back with free, and avoid leaks and dangling pointers.

So far every array had a size fixed when you wrote the program. But often you only learn the size while the program runs — how many students in this class? How many lines in this file? Dynamic memory allocation asks the operating system for memory at run time, from a region called the heap.

#Memory leaks

A memory leak happens when you lose the last pointer to a block without freeing it. The memory stays reserved until the program ends. In long-running programs (servers, games) leaks slowly eat all RAM.

Golden rules
  1. Check every malloc/calloc/realloc result for NULL.
  2. Every malloc needs exactly one matching free.
  3. Never use memory after free (set the pointer to NULL).
  4. Never free the same block twice, or free memory you did not allocate.
Finding leaks

On Linux, run your program with valgrind ./prog, or compile with -fsanitize=address. Both report leaks and use-after-free bugs with exact line numbers.

Variables vanish when a program ends. Files keep data on disk. C works with files through a FILE * pointer from stdio.h.

Common file bugs
  • Not checking fopen for NULL (wrong file name or folder).
  • Opening with "w" when you meant "a" — your old data is erased instantly.
  • Using char instead of int for fgetc's result, so EOF is never detected properly.
  • Forgetting fclose: buffered data may never reach the disk.
